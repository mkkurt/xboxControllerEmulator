# CloudPad Security & Anti-Piracy Strategy

## Current Status (Audit Result)
The current implementation uses **Offline Checksum Validation**.
- **Mechanism:** Checks if the license key follows a mathematical pattern based on a secret string.
- **Security Level:** 🔴 **Low**
- **Vulnerability:** The "secret" key is hardcoded in the script. Anyone who opens the code can generate infinite valid keys.
- **Suitability:** Okay for a quick prototype, **NOT suitable** for a mature commercial product.

## The "Best Practice" Solution
To protect your revenue, we must move to **Online Verification**.

### 1. Direct Sales (Gumroad)
We will integrate the **Gumroad License API**.
- **How it works:** When the user enters a key, the app asks Gumroad: *"Is this key valid and active?"*
- **Benefits:**
    - **Impossible to Fake:** Keys are generated by Gumroad, not a math formula.
    - **Revocable:** If you refund a user, their key stops working.
    - **Device Limits:** You can limit how many "seats" a key has (e.g., 1 PC).

### 2. App Store (macOS/Windows)
The App Store handles security for us.
- **Mechanism:** Apple/Microsoft wrap the app in their own DRM (FairPlay).
- **Action:** We disable our custom license check for Store builds and rely on the Store's receipt validation.

## Implementation Plan
1.  **Modify `license_validator.py`:**
    - Add `verify_with_gumroad(key)` function.
    - Use `requests` to call `https://api.gumroad.com/v2/licenses/verify`.
    - Cache the result locally (encrypted/obfuscated) so it works offline for a few days.

2.  **Obfuscation (Optional):**
    - Use `PyInstaller`'s encryption key to hide the source code slightly.
    - *Note:* Python is hard to fully secure. Online validation is the only real barrier.

## Recommendation
**Implement Gumroad API Verification immediately.**
It is the industry standard for indie software and provides robust protection with minimal effort.
